# Коммуникации SkeekS CMS

`skeeks/cms-communication` собирает переписку с клиентами в CRM: почтовые
ящики, боты мессенджеров, уведомления клиентам и рассылки. Каждое письмо и
сообщение связывается с лидом, компанией, клиентом или любой другой сущностью
CRM и появляется в их ленте рядом со звонками, задачами и комментариями.

Версия 1.0 — почта. Боты, уведомления клиентам и рассылки — следующие этапы.
Согласованная архитектура и этапы — в [ARCHITECTURE.md](ARCHITECTURE.md),
правила разработки — в [AGENTS.md](AGENTS.md), изменения — в
[CHANGELOG.md](CHANGELOG.md).

Каналы подключаются отдельными пакетами-драйверами:

- `skeeks/cms-communication-imap` — почтовые ящики по IMAP/SMTP на любом сервисе.

## Установка

1. `composer require skeeks/cms-communication skeeks/cms-communication-imap`,
   затем `php yii cms/migrate`.
2. Задать ключ шифрования паролей ящиков — длинную случайную строку — в
   защищённых параметрах проекта или в окружении:

   ```php
   // params, не попадающие в репозиторий
   'cms-communication' => ['secretKey' => '...'],
   ```

   или переменная окружения `CMS_COMMUNICATION_SECRET_KEY`. Без ключа пароли
   сохранить нельзя. Если ключ сменить, сохранённые пароли перестанут
   расшифровываться — их придётся ввести заново.

## Что есть в админке

- **Настройки → Почтовые ящики** — одна форма: адрес, имя отправителя, логин и
  пароль приложения. Логин по умолчанию равен адресу, серверы IMAP/SMTP
  подставляются сами для Яндекса, Mail.ru, Gmail, Rambler, Outlook и для
  корпоративных доменов на их почте (по MX). Пароль после сохранения не
  показывается; пустое поле при правке оставляет прежний. В карточке ящика —
  «Проверить подключение», «Получить письма», вкладка «Доступ сотрудников»:
  чтение (все письма / только связанные с его лидами, компаниями и клиентами /
  нет), отправка (на любой адрес / только своим / нет), ящик по умолчанию,
  управление ящиком, ответственный; вкладка «Сбор писем» — собрать письма за
  больший срок (до всех писем ящика), они считаются прочитанными. У ящика могут
  быть свои настройки хранения файлов.
- **Настройки → Настройки почты**: «Хранение файлов» (по умолчанию
  «Минимальный»: картинки и вложения остаются в ящике и загружаются при
  открытии; «Экономный», «Полный», «Выборочно», предел размера, сроки хранения
  копий), «Сохранить файлы в CRM» (загрузить файлы уже полученных писем
  насовсем), «Очистка файлов» (удалить копии по условиям).
- Редкий случай — несколько адресов приходят в один логин (алиасы, пересылка
  в папки): в форме ящика выбрать «Письма приходят в другой ящик». Подключения
  отдельно доступны по адресу `cmsCommunication/admin-cms-comm-connection`.

- **Почта** (главное меню) — как почтовая программа: слева папки «Все письма»,
  «Мои клиенты» (привязанные к лидам, компаниям, клиентам), «Без привязки» и
  «Входящие»/«Отправленные» каждого ящика с чтением «всё»; в середине список,
  справа письмо с ответом. Поиск по всей переписке: находится переписка, в
  любом письме которой есть слова запроса (отправитель, получатели, тема,
  текст). У каждого ящика также «Архив», «Спам» и «Корзина». Отметки
  «прочитано» у каждого сотрудника свои; на телефоне — одна колонка. Вкладка
  «Таблица» — прежний список. Папка «Черновики»: начатое письмо сохраняется
  само, с файлами, и дописывается позже; черновик ответа продолжается кнопкой
  «Ответить». Неотправленные черновики удаляются через срок из «Настроек
  почты» (по умолчанию 90 дней).
- **Разбор писем**: в письме — «Привязать» (письмо или всю переписку к лиду,
  компании, клиенту или сделке, выбор с поиском), «×» у привязанной записи
  (отвязать письмо или всю переписку — тогда новые письма к ней сами не
  привяжутся), «Создать ▾» — задача, лид или сделка в стандартном окне CRM,
  заполненном из письма; у письма появляется отметка «Задача №…». То же — в
  меню строки списка (правая кнопка мыши или «⋮»). Требует «создания из
  источника» в `skeeks/cms`. «Ответственный» за переписку (меню, папка «Мне
  назначено», фильтр) и фильтр «Привязка» по умолчанию скрыты; включаются
  `communication.showAssignee` и `communication.showLinkedFilter`.
- Администратор в «Почте» видит, пишет и управляет письмами по своим строкам
  доступа к ящикам, как любой сотрудник.
- **Действия в ящике** (право «Управление письмами» в доступе к ящику):
  «Удалить», «В архив», «Это спам» / «Не спам», «Восстановить», «В папку»
  (папки самого ящика) и цветные метки — для письма, выбранных писем или всех
  писем папки. Письмо сразу уходит из папки, а в почтовом ящике переносится
  фоновой задачей; если сервер отказал, письмо остаётся на месте с причиной.
  Письма, перенесённые или удалённые в самой почте (например, в Яндексе),
  при следующем приёме оказываются там же и не задваиваются.
- **Мои настройки почты** (ссылка под папками) — у каждого сотрудника свои:
  уведомления о новых письмах по каждому ящику (в колокольчике CRM; несколько
  писем одного приёма — одним уведомлением), подпись для каждого ящика,
  шаблоны быстрых ответов — личные и общие для ящика. Шаблон вставляется
  кнопкой «Шаблоны» в форме письма.
- **Написать письмо** — кнопка у email в карточках лида, компании и клиента.
  Отправитель — ящики, с которых сотрудник может писать; письмо попадает в
  ленту карточки.
- В карточке подключения — **«Проверить подключение»** (сразу входит на IMAP и
  SMTP и показывает ответ серверов) и **«Получить письма»**.
- **Отправить клиенту** — окно, которое открывают другие пакеты (КП, позже
  счета) у своего документа. Наверху — что отправляется: название, личная
  ссылка и файлы. Ниже — контакты клиента из CRM (email и телефоны лида, его
  компании и клиента, людей компании, компании и клиента сделки; только
  записи, которые сотрудник видит). Щелчок по контакту выбирает канал и
  получателя. «Письмо» — обычная форма письма из ящика сотрудника с текстом,
  ссылкой «Открыть …» (в письме это кнопка) и файлами вложением; письмо
  попадает в переписку, ленту и «Отправленные». «СМС» — текст, который можно
  поправить, и предпросмотр: в конце добавляется личная ссылка. СМС уходят
  через провайдера СМС сайта («Настройки → SMS провайдеры», основной или
  первый) и видны в ленте лида, компании, клиента.
- **Прикрепить из…** в форме письма — меню документов установленных пакетов
  («КП», «Счёт»). Выбранный документ ложится в текст ссылкой (её можно
  передвинуть) и в письмо файлами; убрать — «×» у документа. Черновик его
  помнит.

- **Настройки → Темы рассылок** — темы рекламных рассылок сайта («Акции и
  скидки», «Новости студии»…): название, описание для клиента, активна.
  Кнопка «Добавить начальные темы» добавляет четыре стандартные темы, которых
  ещё нет. У каждой рассылки одна тема; клиент отписывается от тем.
- **Рассылки в карточках** лида, компании и клиента: блок «Рассылки» — у
  каждого email и телефона состояние по темам (подписан, на каком основании,
  отписан, стоп-лист). Кнопка у контакта открывает «Подписки на рассылки»:
  отметить согласие («подписался на сайте», «дал согласие устно», «нет
  согласия — холодный контакт»), отписку или стоп-лист с комментарием.
  Согласие и отписка хранятся у самого адреса или номера: один адрес лида,
  компании и клиента — одна отметка. У контакта в стоп-листе в карточке
  красная метка.
- В окнах «Написать» и «Отправить клиенту» — предупреждение, если адрес или
  номер отписан от всех рассылок, пожаловался или не принимает письма.
  Личное письмо при этом уходит: отписка касается только рекламы, служебные
  и личные письма она не блокирует.
- **Лиды → вкладка «Импорт»** (рядом с «Отчётом») — список получателей из CSV (UTF-8 или
  Windows-1251, разделитель — точка с запятой, запятая или табуляция) или
  таблица, скопированная из Excel: колонки → ответственный, тема рассылки и
  основание согласия для всего файла → предпросмотр с повторами (email,
  телефон, ИНН, название среди лидов, компаний и клиентов, повторы внутри
  файла) → импорт. Новые лиды — с источником «Рассылка» и ответственным,
  значения файла — в описании лида; ответственный получает одно уведомление.
  Тема и основание отмечаются у контактов и новых лидов, и повторов; отписку
  клиента импорт не снимает, настоящее согласие не превращает в «холодное».
  Больше 200 строк импортируется в фоне. Отчёт — по каждой строке. На
  вкладке — стандартный список загруженных таблиц (сотрудник видит свои,
  администратор — все) и кнопка «Загрузить таблицу»; загрузка и карточка
  импорта (колонки, предпросмотр, отчёт) открываются в стандартном окне
  поверх вкладки, список обновляется, когда окно закрывают.

- **Рассылки** (главное меню, сразу под «Почтой») — кампании: письмо по теме
  рассылки группе лидов (по фильтру — статус, этап, источник, ответственный —
  или лиды загруженной таблицы «Лиды → Импорт»). Тема письма и текст с
  подстановками `{Имя}`, `{Компания}`, `{Менеджер}`, `{Ссылка}` (кнопка на
  предложение), `{Отписаться}`; предложение — без него, один документ всем
  (общая Презентация, у каждого своя ссылка) или каждому своё КП из шаблона
  (создаётся, когда уходит его письмо). Отправитель — ящик ответственного за
  лида или выбранный ящик. Карточка черновика: кто получит письмо, кто исключён
  и почему, с каких ящиков и примерно за сколько дней; предпросмотр на любом
  получателе; «Отправить тестовое письмо себе»; «Запустить». Запущенная
  кампания: пауза, продолжить, отменить; итоги в процентах и отчёт по каждому
  получателю (отправлено, ошибка, открыл предложение, ответил, принял КП,
  отписался). Настройки «Задача менеджеру, когда клиент открыл предложение /
  ответил». **Получатели по одному и личные письма**: «+ Добавить
  получателя» — лид, компания (её email или email человека компании) или
  клиент; у каждого получателя может быть своё письмо — тема и текст вместо
  шаблона (обязательны `{Отписаться}` и, если есть предложение, `{Ссылка}`),
  видно, кто его подготовил (сотрудник или ИИ и через что). Такие получатели
  входят в любую аудиторию; аудитория «Только добавленные получатели» — только
  они. Письмо получателя, который ещё ждёт отправки, можно поправить и после
  запуска. Право «Рассылки: создавать и запускать кампании»
  (`cmsCommunication/admin-cms-comm-campaign`), у администраторов есть сразу.
- **Почтовый ящик → вкладка «Рассылки»** — скорость писем кампаний с ящика:
  писем в день (по умолчанию 30, вместе с личными письмами менеджера за день —
  из CRM и из самой почты), пауза между письмами (случайная, по умолчанию
  60–180 секунд), рабочие часы и дни (по умолчанию пн–пт 9–18); сколько ушло
  сегодня, сколько ждёт и когда следующее письмо.

Ящиками и подключениями пока управляют администраторы.

## Рассылки: согласие, отписка, проверка перед отправкой

- Контакт рассылок — `models\CmsCommContact` (сайт, вид `email`/`phone`,
  значение в нижнем регистре или цифрами `79991234567`, код личной ссылки).
  Состояние по теме — `CmsCommContactTopic`, стоп-лист — `CmsCommSuppression`.
  Пишет их только `services\MailingConsents` (`subscribe`, `unsubscribe`,
  `suppress`, `unsuppress`, `state`, `summary`).
- **Можно ли отправить рекламу**: `services\MailingPolicy::check($siteId,
  'email'|'sms', $value, $topicId, MailingPolicy::MODE_MANAGER|MODE_SERVICE)`
  и `checkMany()` для списка — `['allowed', 'reason', 'message', 'consent']`.
  Ящик менеджера (`manager`) может писать «холодным» контактам и контактам без
  отметок; сервис рассылок (`service`) — только при согласии. Причины отказа:
  нет контакта, тема выключена, отписан от всех, жалоба, не доставляется,
  отписан от темы, нет согласия. Личные и служебные письма эту проверку не
  проходят; `MailingPolicy::warnings()` — для предупреждения в окнах.
- **Письмо рассылки**: `ComposeForm::$cms_comm_topic_id` (задаётся кодом
  кампании, из запроса не загружается) — одному получателю без копий,
  проверка политики, ссылка «Отписаться» шаблона
  `https://sx-unsubscribe.invalid/` (`Unsubscribe::PLACEHOLDER`) становится
  личной ссылкой получателя, без неё в конец добавляется строка «Отписаться
  от рассылки»; у отправленного письма заголовки `List-Unsubscribe` и
  `List-Unsubscribe-Post` (RFC 8058).
- **Страница отписки** `/~unsub/<код>?t=<тема>&m=<письмо>` без входа, не
  индексируется: темы галочками, «Отписаться от всех» и «по всем каналам»
  (все адреса и телефоны лидов, компаний и клиентов этого контакта). `POST`
  на тот же адрес с `List-Unsubscribe=One-Click` — отписка от темы письма (от
  всей рекламы, если темы в ссылке нет) кнопкой почтовой программы.
- Импорт: `services\LeadImport` (`create`, `preview`, `run`), повторы —
  `services\CrmDuplicates`, задача `comm.import.leads`. Строки импорта
  (`CmsCommImportRow`: создан лид, повтор какой записи, пропущено и почему) —
  отчёт и будущая аудитория кампании.

## Кампании рассылок

- Кампания — `models\CmsCommCampaign`, получатели и отчёт —
  `models\CmsCommCampaignRecipient` (одна строка на лида: уникальный ключ
  кампания + запись CRM, поэтому одному лиду кампания пишет один раз). Всё
  делает `services\Campaigns`: `summary()` (аудитория через `forManager()`
  запускающего, первый email лида, исключения с причиной:
  `MailingPolicy::checkMany()` в режиме канала, повтор адреса, закрытый лид из
  импорта, `allowedRecipients`, нет ящика), `launch()` (получатели
  фиксируются один раз), `pause()`, `resume()`, `cancel()`, `preview()`,
  `sendTest()`, `deliver()` (одно письмо: повторная проверка политики, письмо и
  предложение в одной транзакции с отметкой получателя), `refresh()` и
  `stats()` (отчёт), `taskOnOpen()`, `onIncoming()` (ответы).
- **Получатели по одному** (сотрудник в карточке, ИИ через MCP):
  `Campaigns::addRecipient($campaign, $record, $user, ['address', 'name',
  'subject', 'body_html', 'by' => 'user'|'ai', 'client' => 'crm'|'mcp:<клиент>'])`
  — до запуска, запись (лид, компания, клиент) должна быть видна сотруднику,
  адрес — один из `Campaigns::recordAddresses()`; строка получателя в статусе
  `draft` с личным письмом и отметкой, кто его подготовил (`text_by`,
  `text_client`, `text_user_id`, `text_at`). `setText()` меняет письмо, пока
  оно не ушло (пустые тема и текст — снова шаблон), `removeRecipient()`
  убирает до запуска, `textErrors()` проверяет текст. При запуске добавленные
  объединяются с аудиторией (их адрес, имя и письмо главнее) и проходят те же
  исключения. Отправитель компании и клиента — их первый менеджер
  (`Campaigns::responsibleOf()`).
- Каждое письмо — обычное письмо `MailComposeService::queue()` с
  `ComposeForm::$cms_comm_topic_id` (личная отписка, `List-Unsubscribe`),
  `$cms_comm_campaign_id` (отметка `cms_comm_message.cms_comm_campaign_id`),
  `$record` (лид — связь и запись CRM отправки, без поиска по видимости в
  задаче) и `$sendableInstances` (документ, сделанный кодом): лента лида,
  «Отправленные», ответ привязывается как у любого письма. `SendContext::$campaignId`
  говорит пакету документа, что отправка — из кампании.
- **Канал кампании** — `communication.campaignChannels`
  (`campaign\CampaignChannelInterface`: `policyMode()` для `MailingPolicy`,
  `assignSenders()` при запуске, `start()`, `deliver(CampaignLetter)`).
  В пакете — `campaign\MailboxCampaignChannel` («Ящики менеджеров»,
  `MODE_MANAGER`): задача `comm.campaign.mailbox` на ящик (`resourceKey`
  ящика, `skip`) отправляет одно письмо и ждёт в очереди случайную паузу или
  начало следующего рабочего периода (`services\MailboxPace`, дни и часы — в
  часовом поясе форматтера CRM); расписание `comm.campaign.tick` раз в 5 минут
  продолжает идущие кампании и завершает пустые. Сервис рассылок (4C)
  добавит свой канал с `MODE_SERVICE`.
- **Предложение** — источник отправляемого с
  `send\CampaignSourceInterface`: `sharedItems()` (документ всем),
  `templates()` и `createFromTemplate()` (документ каждому, в транзакции
  письма), `states()` (открыл, принял — для отчёта). Реализация —
  `skeeks/cms-proposal`. Правило «задача при первом открытии» остаётся в пакете
  документа и спрашивает `Campaigns::taskOnOpen()`; задачу по ответу ставит
  `services\CampaignTasks`.
- Ссылки писем, сделанных в фоновой задаче, строятся от
  `CommunicationComponent::siteUrl()`: адрес веб-запроса, иначе
  `communication.baseUrl`, иначе главный домен сайта. Стенд с копией боевой
  базы задаёт `baseUrl` своего адреса.
- Новые настройки скорости ящика действуют со следующего шага задачи: ящик,
  уже ждущий следующего дня, начнёт по ним с утра.

## Отправить клиенту: контракт для пакетов

Пакет, который отправляет клиентам свои документы, ничего не знает о
каналах. Он описывает «отправляемое» и регистрирует источник:

```php
// config пакета
'components' => ['communication' => ['sendables' => ['proposal' => ProposalSendableSource::class]]],
```

- `send\SendableSourceInterface` (тип `[a-z][a-z0-9_-]*`, ссылка на документ —
  `тип:id`, например `proposal:12`): `title()` — название в меню («КП»);
  `find($id, $user)` — документ, если сотрудник может его отправлять, иначе
  `null` (права решает пакет); `suggest($user, $q, $record, $limit)` — список
  для «Прикрепить из…» (`id`, `title`, `hint`), документы карточки `$record`
  первыми.
- `send\SendableInterface` — сам документ:
  - `getSendTitle()` — название (тема письма, подпись в форме);
  - `getSendText()` — короткий текст, который сотрудник может поправить
    (без оформления: так он уходит в СМС); если у документа текст с
    оформлением, он дополнительно реализует `send\SendableHtmlInterface`
    (`getSendHtml()`), и письмо начинается с этого HTML;
  - `getSendButton()` — надпись кнопки/ссылки («Открыть КП»);
  - `getSendFiles()` — `send\SendFile[]`: файл хранилища
    (`SendFile::storage($file)`) или локальный путь (`SendFile::path(...)`,
    канал сам кладёт его в хранилище); вызывается и для предпросмотра;
  - `getSendRecords()` — записи CRM (лид, компания, клиент, сделка): их
    контакты предлагаются получателями, отправка попадает в их ленту;
  - `createSendLink(SendContext $context)` — личная ссылка этой отправки:
    в контексте канал (`email`, `sms`, позже `telegram`, `max`), получатель
    (email в нижнем регистре или телефон цифрами `79991234567`), имя, запись
    CRM получателя и сотрудник; пакет сохраняет свою запись отправки с кодом и
    возвращает абсолютный URL; своё состояние можно положить в
    `$context->ref`;
  - `afterSend(SendContext $context, CmsCommMessage $message)` — тот же
    контекст и созданное сообщение (письмо или СМС, ещё не доставлено — его
    статус меняется позже): пакет запоминает сообщение в своей записи
    отправки, пишет свою запись ленты.
- Одна отправка — один `createSendLink()` и один `afterSend()` в одной
  транзакции с сообщением: исключение в любом из них откатывает всё, и
  неудачная отправка не оставляет «висящих» ссылок. Если отправку отклонили
  проверки (адрес, номер, права), пакет не вызывается вовсе.
- Открыть окно: `MailUi::sendOnClick('proposal:12', $record)` (onclick кнопки)
  или `MailUi::sendUrl(...)`; `$record` — карточка, из которой открыто окно.
  Без окна (API, бот, ИИ): `SendService::request('proposal:12', ['channel' =>
  'sms', 'recipient' => '+7…', 'text' => '…'])` и `SendService::send()`;
  ошибки — `send\SendException::$errors` по полям.
- Каналы — `communication.channels` (`send\SendChannelInterface`): канал сам
  решает вид (письмо — кнопка и вложения, СМС — текст и ссылка) и создаёт
  сообщение. Драйверы мессенджеров добавляют свои каналы, отправляемое не
  меняется.
- В письме ссылка до отправки — заглушка `https://sx-send.invalid/<тип>/<id>`;
  при отправке она становится кнопкой с личной ссылкой, а если сотрудник её
  удалил — кнопка добавляется в конце.
- Образец минимальной реализации — `tests/support/SampleSendable.php` (только
  для тестов и проверки на стенде, в рабочей конфигурации не регистрируется).
  Настоящая реализация — КП `skeeks/cms-proposal` (`send\ProposalSendable`).
- Отказ пакета отправлять документ (пустой, истёк) —
  `SendException(['sendable' => '…'])` из `createSendLink()`: окно и форма
  письма показывают его, ничего не создаётся.

## Проверки ссылок

`services\LinkChecks::reason($sentAt, $ip, $userAgent, $signals)` говорит,
похоже ли открытие личной ссылки на проверку почтовой службой или защитной
системой, которая запускает скрипты в настоящем браузере (проверка ссылок
Outlook, Proofpoint, антиспам Яндекса и Mail.ru):

- `early` — меньше 30 секунд после того, как письмо ушло (`message_at`
  отправленного сообщения);
- `network` — сети почтовых служб и защитных систем (`LinkChecks::NETWORKS`,
  IPv4 и IPv6, плюс `communication.linkCheckNetworks` сайта). Публичных
  облаков в списке нет намеренно: клиенты сидят там через VPN;
- `browser` — автоматический браузер (`webdriver`, нет языков, экран нулевого
  размера — признаки передаёт скрипт страницы) или известный User-Agent
  предпросмотра ссылок.

Пакет страницы (КП, позже счета) хранит такое открытие с причиной, пишет в
ленту «возможно, проверка ссылок» и не даёт ему статуса, уведомления и
задачи. Роботы без скриптов отсеиваются раньше: страница засчитывает
просмотр только своим сигналом.

## Сообщение с сайта

`services\SiteMessages::receive()` — входящее сообщение, которое клиент
написал на странице сайта (например «Задать вопрос» на странице КП), без
почтового ящика: канал `site`, переписка по ключу страницы
(`site:proposal:12`), связи с записями CRM — сообщение видно в их ленте как
«Сообщение с сайта». Кто может писать (защита от спама, лимиты) и кого
уведомить, решает вызывающий пакет; транзакция — его.

## Как это работает

- Приём — фоновая задача `comm.mail.poll` на полосе `communication`, по
  расписанию `cms-agent` раз в 2 минуты (`comm.mail.poll-all`; после установки
  выполнить `php yii cmsAgent/init`). Забираются «Входящие» и «Отправленные»,
  при первом приёме — последние 30 дней (`communication.initialDays`).
- Письмо хранится один раз, даже если лежит в нескольких ящиках. Привязка к
  лиду (новому или в работе), компании и клиенту — по точному совпадению адреса;
  ответы с другого адреса привязываются по цепочке. Внутренняя переписка (все
  участники — наши адреса и адреса на доменах наших ящиков) не привязывается.
- Отправка — задача `comm.mail.send`: SMTP ящика, затем копия в «Отправленные»,
  если сервер не сохранил её сам. Письмо с неизвестным исходом не отправляется
  повторно.
- Нужен обработчик очереди: `php yii cms-job/worker --queue=communication`
  (или общий диспетчер `cms-job/worker`).
- `communication.allowedRecipients` ограничивает получателей (например
  `['@skeeks.com']` на стенде с копией боевой базы). `communication.allowedPhones`
  — то же для СМС (номера в любой записи); если `allowedRecipients` задан, а
  `allowedPhones` пуст, СМС не уходят никуда.
- СМС «Отправить клиенту» — задача `comm.sms.send` (полоса `communication`):
  сообщение канала `sms` в переписке номера, запись провайдера
  (`cms_sms_message`) хранится в `provider_ref`. Повторно не отправляется.

- Действия в ящике — задача `comm.mail.apply` подключения (та же блокировка,
  что у приёма); приём заодно сверяет ящик с CRM.

- Импорт больше 200 строк — задача `comm.import.leads` (полоса
  `communication`, можно остановить; повторный запуск продолжает с
  несделанных строк).

- Кампании рассылок — задачи `comm.campaign.mailbox` (письма ящика по его
  скорости) и `comm.campaign.tick` (раз в 5 минут, после установки выполнить
  `php yii cmsAgent/init`), полоса `communication`.

Пока не сделано: правила разбора входящих (автолиды, автоответ, стоп-список),
сервис рассылок (этап 4C), списки получателей (компании и люди компаний
массово из разделов CRM, сегменты по условиям).

## Чтение для ИИ-клиентов (MCP/REST)

Если установлен `skeeks/cms-mcp`, пакет добавляет инструменты чтения почты и
рассылок (`src/mcp`, scope `cms.communication.read`; регистрация через
`params['cmsMcp']` в `src/config/common.php`, без `cms-mcp` она ни на что не
влияет):

- `cms_comm_message_list` — письма, СМС и сообщения с сайта по клиенту, ящику,
  переписке, периоду, направлению, поиску; `cms_comm_message_get` — одно письмо;
  `cms_comm_conversation_get` — переписка целиком. Текст — собственный текст
  письма без цитат, подписи и HTML, длина ограничена, вложения только
  названиями.
- `cms_comm_account_list` — ящики сотрудника без подключений и паролей;
  `cms_comm_topic_list` — темы рассылок.
- `cms_comm_mailing_check` — «можно ли писать»: `MailingPolicy::checkMany()`
  для контактов клиента или списка адресов по теме, с причинами отказа;
  `cms_comm_contact_state_get` — стоп-лист, подписки и отписки контактов.

В общей истории клиента (`cms_crm_history_get`) письма описывает
`mcp\MessageHistoryDescriber` (тот же доступ, что у ленты), отписки и согласия
даёт `mcp\MailingHistorySource`, раздел `mailing` обзора клиента —
`mcp\MailingOverviewContributor`. Видимость — `CmsCommMessageQuery::forManager()`,
как в разделе «Почта». Адреса и телефоны замаскированы, пока не передан
`include_contacts=true`; ссылка отписки `/~unsub/` не выдаётся никогда.
Письма с отметкой ИИ отдают `prepared` (OAuth-клиент, пользователь, время,
`edited`).

Тест: `COMM_MCP_TEST=local php tests/mcp-read.php` на локальном сайте с
`cms-mcp` (только чтение).

## Действия ИИ-клиентов: личные письма с предложением (MCP/REST)

Инструменты действий (`mcp\CommunicationActionToolProvider`) — тонкие
адаптеры над сервисами. Подготовка (черновики, кампании, темы) требует scope
`cms.communication.write`, отправка проверенного черновика — отдельного
`cms.communication.mail_send`, которого подготовка не даёт; статус отправки —
`cms.communication.read`. Кампанию не запускает ни один инструмент. Права
`cms.communication.send` (СМС и звонки `cms-mcp`) письма не касаются.

- `cms_comm_draft_create` — черновики личных писем, режим по умолчанию.
  Черновик ложится в «Черновики» ответственного за клиента (его ящик по
  умолчанию; ответственный — `Campaigns::responsibleOf()`) или в указанный
  ящик `cms_comm_account_id`, если OAuth-сотрудник может с него отправлять.
  Черновик сохраняет `MailDrafts`, а проверяет форма письма владельца
  (`ComposeForm::validate()` — ящик, адреса, «только свои», тема, документ),
  как при отправке из «Почты». Предложение (`offer: "proposal:<id>"` —
  общая Презентация или КП этого клиента) кладётся как «Прикрепить из…»,
  `{Ссылка}` в тексте — место кнопки; личная ссылка создаётся при отправке.
  Обязательна тема рассылки `cms_comm_topic_id`: письмо из такого черновика
  уходит одному получателю с личной ссылкой «Отписаться» и
  `List-Unsubscribe` (`MailDrafts::applyAiDraft()` перед проверкой формы).
- `cms_comm_campaign_create` — черновик кампании «Только добавленные
  получатели» (тема, отправитель, общая Презентация или КП каждому из
  шаблона, задачи при открытии и ответе). Нужно право «Рассылки».
- `cms_comm_campaign_recipient_add` — получатели черновика кампании с
  личной темой и текстом (`Campaigns::addRecipient()`, `by=ai`). `{Ссылка}` и
  `{Отписаться}` добавляются в конец, если их нет. Запускает кампанию только
  сотрудник в карточке кампании.

Проверки по каждому клиенту (отказ — `status=refused`, `reason`, `message`,
остальные строки выполняются): клиент виден OAuth-сотруднику
(`forManager()`), у него есть email, адрес разрешён `allowedRecipients`,
`MailingPolicy` по теме (отписан от темы или всех, жалоба, недоставка),
письмо клиенту за `recentDays` (исходящие письма, привязанные к записи),
это предложение клиенту за `recentDays` (`send\SendHistoryInterface` источника
документа), черновик ИИ или кампания, уже ждущие этого клиента; КП другого
клиента не прикладывается. Без `confirm=true` ничего не сохраняется — ответ
показывает, что будет сделано и кому откажут (`requires_confirmation`).

Лимиты — `communication.aiLimits` (по умолчанию `perCall` 20 строк за вызов,
`perDay` 100 черновиков и получателей в день на сотрудника по часовому поясу
CRM, `recentDays` 30). Дневной счёт — по отметкам ИИ: черновики, письма из
них, личные письма получателей кампаний.

**Отметка «Подготовлено ИИ»** (`services\AiMark`, миграция
`m261029_100000`): `prepared_by=ai`, `prepared_client=mcp:<название
OAuth-клиента>`, `prepared_user_id`, `prepared_at` у черновика, письма и
кампании; у получателя кампании — `text_by=ai`, `text_client` и
`text_edited_by`. Ставит её только сервер по OAuth-токену текущего вызова
(`McpComponent::getCurrentClientName()`); поля аргументов и формы её не
задают и не снимают. Письмо из черновика ИИ получает отметку от своего
черновика (только собственного) и `prepared_edited`, если сотрудник изменил
тему или текст (`prepared_hash`); правка личного текста получателя
сотрудником оставляет отметку и пишет `text_edited_by`. Отправку предложения
отмечает запись ленты (`data.ai` с `sent_by`). Видно: в «Черновиках»
(значок «ИИ»), в форме письма, на странице письма, в ленте карточки
(«Подготовлено ИИ … по запросу … · отправил …»), в карточке кампании и в
колонке «Письмо» получателей, в отправках карточки предложения.

Журнал: каждый вызов пишет `tool.start`/`tool.finish` `ApiLogService` с
`oauth_client_id` и пользователем, действие — запись `ai.action` (созданные
id, причины отказов) в той же категории транспорта.


### Отправка проверенного черновика через API

Полный цикл: подготовка → проверка → согласие человека → отправка → статус.
Отправляется только сохранённый черновик в «Черновиках» OAuth-сотрудника
(создать его в своём ящике — `cms_comm_draft_create` с `cms_comm_account_id`),
чтобы адресат и текст не менялись незаметно между проверкой и отправкой.

1. `cms_comm_draft_check {draft_id}` (`cms.communication.write`) —
   `services\AiSend::check()`: черновик открывается так же, как в «Почте»
   (`MailDrafts::fill()`, `applyAiDraft()`, `ComposeForm::validate()` — ящик и
   право отправки с него, адреса, «только свои клиенты», `MailingPolicy` темы,
   документ) плюс правила API: клиент CRM привязан, один адрес из его карточки
   (`Campaigns::recordAddresses()`), без копий, есть тема, нет письма клиенту
   и отправки этого предложения за `recentDays`, предложение можно отправить
   (`send\SendRefusalInterface`: срок, страница), дневной лимит `sendPerDay`.
   Ничего не отправляет, личной ссылки и открытия не создаёт; предпросмотр —
   тема, текст и HTML с неработающей кнопкой (`#offer-preview`). Пройденная
   проверка возвращает `check_token` — отпечаток черновика, ящика, адресов,
   темы письма, текста, предложений, темы рассылки и клиента.
2. `cms_comm_draft_send {draft_id, check_token, idempotency_key, confirm:true}`
   (`cms.communication.mail_send`): отпечаток считается заново — любое
   изменение черновика после проверки даёт `changed_after_check`. Письмо
   ставит в очередь `MailComposeService::queue()` (личная ссылка,
   «Отписаться», `List-Unsubscribe`, лента, привязки, задача отправки) в одной
   транзакции со строкой `cms_comm_api_send` ключа (миграция `m261101_100000`),
   затем черновик удаляется. Повтор с тем же ключом и тем же `draft_id` +
   `check_token` возвращает прежний результат (`repeated: true`), с другими —
   `idempotency_key_reused`; отказ ключ не занимает. Параллельный повтор
   ждёт уникального индекса и получает результат первого.
3. `cms_comm_send_status {idempotency_key | cms_comm_message_id}`
   (`cms.communication.read`): `state` — `queued`, `sending`, `sent` (принято
   почтовым сервером отправителя, не доставка), `failed` с ошибкой, `unknown`
   (повторно не отправляется); `delivery` — `not_confirmed` или `bounced`
   (в переписке пришло автоматическое письмо о недоставке, или адрес отмечен
   недоставляемым после отправки); `offers` — `send_id`, честное открытие
   (`opened`, `views_count`) и отдельно `link_checks_count` проверок ссылок
   почтовыми службами (`CampaignSourceInterface::states()`); `replies` —
   ответы людей в переписке. Чтение статуса ничего не открывает. Неизвестный
   ключ — `not_found`: письмо не отправлялось.

Письмо, отправленное через API, отмечено «отправлено ИИ через API (клиент)»:
`AiMark::of()` находит строку `cms_comm_api_send`; запись ленты об отправке
предложения хранит `data.ai.sent_via`.

Темы рассылок через API — `cms_comm_topic_create`, `cms_comm_topic_update`
(`services\MailingTopics`, `cms.communication.write`, только администратор, как
раздел «Темы рассылок»; название уникально, правка частичная). Отправка тему
никогда не создаёт; пустой `cms_comm_topic_list` возвращает `setup_required`.

Тест: `AI_SEND_TEST=local php tests/ai-send.php` (темы, Презентации,
проверка, отправка, ключ, изменение после проверки, состояния и недоставка,
